# 小程序架构与现状

## 1. 最重要的结论

`miniprogram/` **已为微信原生源码树**：登录/首页/我的/扫码/消息与主要业务页（任务、设备、签到、客户、建筑、报修、报告、巡检）均接真接口。**不再从 uni-app 构建产物更新小程序。**

微信开发者工具 AppID（测试号）：`wx550e3fbd9d3ea9a4`（见 `project.config.json`）。

业务判断、筛选、权限、状态流转、聚合统计均由 backend 负责；小程序只做展示、表单采集与调用接口。权威 API 见 [12-后端接口手册.md](12-后端接口手册.md)。

历史说明：仓库曾长期只含 uni-app 编译产物（`common/vendor.js`、`@dcloudio/uni-ui`）；该依赖已删除。

## 2. 入口和路由

`app.json` 注册 31 个页面，首屏为 `pages/login/index`。没有原生 `tabBar` 配置，项目使用自定义 `components/tab-bar`，并通过 `redirectTo` 在首页、消息、扫码、个人中心之间切换。

主要路由：

```text
login/index
├─ login/password
└─ login/register

index/index
├─ checkin/index → checkin/history
├─ task/index → task/detail → task/system → task/device
│              （已移除 task/action；常规维保与消防设施测试合并为「消防维护」）
├─ customer/index
├─ equipment/index → equipment/list → equipment/detail → equipment/edit
│                                   └→ equipment/form
├─ report/index
├─ building/index → building/detail / building/form
├─ repair/form
└─ repair/index → repair/detail
```

`pages/inspection/*` 为独立巡检测试模块；任务/设备/签到/报修/报告等主业务页已接真接口（非占位壳）。

## 3. 目录职责

| 目录 | 职责 |
|---|---|
| `config/env.js` | `BASE_URL`、环境名 |
| `services/request.js` | 唯一 `wx.request`；Bearer；401 清会话 |
| `services/auth.js` | token/user 读写、登出 |
| `services/upload.js` | `/api/common/upload` |
| `api/index.js` | 手写薄封装（对照手册 12） |
| `components/tab-bar`、`company-drawer` | 原生 TabBar / 公司切换 |
| `pages/` | 页面逻辑、视图和页面配置 |

## 4. 请求与 Token

当前请求链：

```text
页面
→ api/index.js
→ services/request.js
→ config/env.js 中的 BASE_URL（dev 默认 http://localhost:83）
→ Authorization: Bearer <token>
```

Token：

- key：`token`
- 存储：微信同步 storage
- 来源：`POST /api/login` 返回的 Shiro Session ID
- 登出：调用 `/api/logout` 后移除本地 Token

### 已知问题

1. 部分历史路径仍可能引用 `utils/request.js`；新代码应统一走 `services/request.js`。
2. 下载/预览报告需确保合法 download 域名与后端文件路径一致。

## 5. 页面模块现状

| 模块 | 当前作用 | 说明 |
|---|---|---|
| `login` | 密码登录、邀请注册 | 手机验证码页仍为占位 |
| `index` | 公司、应用入口、统计 | `GET /api/fire/home` |
| `task` | 消防维护三级执行 + 情况简述 + 检查项详情 | 已无 `task/action`；含 `conclusion`/`check-detail`；二级「全部正常」 |
| `equipment` | 分组、列表、详情、表单 | 字段以 Domain JSON 为准 |
| `inspection` | 独立巡检测试 | 类目走消防维护模板 API |
| `checkin` | 一屏签到：定位、签到/签退、照片、备注 | 中文地址走 `GET /api/fire/checkIn/reverseGeocode`；提交时后端再解析覆盖地址 |
| `repair` | 报修、派发、完成 | 权限以后端为准 |
| `building` | 建筑 CRUD | 编码后端自动生成 |
| `report` | 报告列表与下载 | 依赖合法 download 域名 |
| `message` | 消息 | 功能较薄 |

## 6. 字段漂移

设备页面为了兼容历史响应，同时处理：

- `equipmentType` / `systemName` / `systemType`
- `expireDate` / `expiryDate` / `warrantyEndDate`
- `model` / `specification` / `specifications`
- `floorNo` / `floor`
- `image` / `imageUrls`

原生重构时不应继续扩大别名集合。建议以 Java Domain JSON 字段为准，在 API 适配层做一次性归一化，并为每个接口记录请求/响应样例。

## 7. 原生重构目标结构

建议的新结构：

```text
miniprogram/
├─ app.js
├─ app.json
├─ app.wxss
├─ config/
│  ├─ env.js
│  └─ constants.js
├─ services/
│  ├─ request.js
│  ├─ auth.js
│  ├─ company.js
│  ├─ task.js
│  ├─ equipment.js
│  └─ ...
├─ models/
│  └─ normalizers.js
├─ components/
├─ pages/
└─ utils/
```

重构完成标准：

- 不再引用 `common/vendor.js` 和 `node-modules/@dcloudio`。
- 页面使用原生 `Page`/`Component` 和 `wx.*`。
- 请求、上传、下载和 401 仅有一个实现。
- Base URL 可按环境切换。
- 页面不再使用硬编码演示业务数据掩盖接口错误。
- 核心流程具备最少的接口冒烟测试或可重复人工验收脚本。
